| D23 | 2026-11-18 | TUI v2 uses a card-cursor model: stock / top discard / each hand card is a navigable tile (4-row ASCII box). `←/→` move the cursor, `Enter` acts on the current tile, `d` discards the selected card, `c` closes with it, `p` passes, `m` enters lay-meld cycle, `a` enters add-to-meld cycle, `Shift+←/→` reorders cards in the hand, `q` quits. The numbered 1..0 action list is removed | The numbered list is scriptable but not playable. The card-cursor model keeps every action physically tied to a card the player sees, matches how one plays with physical cards, and scales to multi-card meld selection without a submenu |
| D24 | 2026-11-18 | Internal deck stays `C/D/H/S` in `conga-core`. The TUI renders cards with a user-visible suit theme chosen via `conga-cli play --suits=french\|spanish` (default `french`). French uses `♣ ♦ ♥ ♠`; Spanish uses `✦ ● ♡ ✚` (bastos / oros / copas / espadas). The log format and the `replay` CLI output stay as the raw `"7C"` serialisation | Keeps the engine, log and protocol unchanged. Theme is a display-only concern; swapping it needs no engine, protocol or log changes. Single-cell glyphs keep the card-tile layout aligned in every terminal |
| D25 | 2026-11-18 | Meld builder uses a cycle model: pressing `m` enters a mode that iterates the already-legal `LayMeld` actions with `←/→`, `Enter` commits, `Esc` cancels. Same model for `a` + `AddToMeld`. No multi-select + validate | Simpler: reuses `legal_actions` directly, no selection-to-meld reconciliation. Cheaper to test and implement. Loses nothing, since the meld solver already enumerates every legal meld the player could want to lay |
| D26 | 2026-11-18 | `Player::act` becomes synchronous: `fn act(&mut self, obs, legal) -> Action`. The m2 `run_player` driver still runs under tokio for transport IO; the trait method is called sync inside the `AwaitAction` branch | Current impl wraps pure CPU work in `impl Future<Output = Action>`, which costs nothing and reads worse. Sync is forward-compatible with rayon when parallel eval lands, and nothing outside `conga-ai` depends on the async signature |
| D27 | 2026-11-18 | Greedy agent: draw whichever source reduces the solver's unmatched total more (tie: stock). Always lay a legal meld or add to a meld when available. Discard the highest-rank unmatched card (ties broken by card index). Close whenever `can_close`. Pass only when no other action is legal. Deterministic | Smallest heuristic that ought to beat Random cleanly. Deterministic means eval runs are reproducible from the match seed alone |
| D28 | 2026-11-18 | Rule-based agent = greedy + discard-safety v1. Scores each legal discard by whether it fits any meld the next seat is visibly building (their `melds_on_table`) or completes a run with a card they recently took from the discard. Among discards tied on greedy value, pick the safest; else fall back to greedy. Per-turn state only | Simplest signal strong enough to beat greedy. Opponent-hand modelling (belief tracker) is m4's business; keeping m3 state-free keeps the two layers independent |
| D29 | 2026-11-18 | The m3 eval harness is headless and calls `rules.legal_actions` → `agent.act` → `rules.apply` directly against the m1 engine, bypassing the m2 server/transport. Duplicate deals: each paired game runs the same `Chance` seed twice with A/B on swapped seats. Single-threaded in m3; rayon deferred | Faster and fewer moving parts. The server's async transport layer serves live play, not batch simulation |
| D30 | 2026-11-18 | The design-doc m3 exit test's "rollouts per second" metric is recorded as "decisions per second" for m3 because baseline agents do no rollouts. The rollouts figure returns in m4 with the search agent | Baseline agents choose deterministically from a legal set; there is no rollout to measure. Decisions/sec captures the same operational concern (how fast eval can run) |
| D31 | 2026-11-18 | Stalemate terminal: a `StandardConga` hand ends as a `Stalemate` when any of the following fires — the engine would do a 4th reshuffle in the same hand (reshuffle count capped at 3), or a `DrawStock` finds both the stock and the reshufflable discard portion empty. On stalemate every seat scores 0, no bonus, dealer rotates normally. `HandResult` gains a `terminal: HandTerminal { Closed, Stalemate }` field so replay and the match log preserve the distinction. Rule clarification C4 in `docs/design.md`. Logged in `docs/plans/m3.md` as new slice 6 ahead of the renumbered exit-test slice 7 | Found in m3 slice 5 playtesting: two deterministic greedy-style agents can cycle a hand forever because `Close` is never offered (no 8-card configuration ever splits into 7-melded + 1 close card). The m1 engine already deferred this terminal case (`standard.rs:436 unreachable!`). Fixing it in the engine (rather than in the harness or in the agent) gives termination for every entry point — eval, server play, TUI — for free. K=3 lets each hand have three full cycles of card mixing before giving up. "Draw" scoring (0 points) matches the "nobody won this hand" reading; residual-scoring was considered and rejected to keep the match outcome non-exploitative (an agent cannot deliberately stall to score opponent residuals) |
