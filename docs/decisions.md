| D23 | 2026-11-18 | TUI v2 uses a card-cursor model: stock / top discard / each hand card is a navigable tile (4-row ASCII box). `←/→` move the cursor, `Enter` acts on the current tile, `d` discards the selected card, `c` closes with it, `p` passes, `m` enters lay-meld cycle, `a` enters add-to-meld cycle, `Shift+←/→` reorders cards in the hand, `q` quits. | D24 | 2026-11-18 | Internal deck stays `C/D/H/S` in `conga-core`. The TUI renders cards with a user-visible suit theme chosen via `conga-cli play --suits=french\|spanish` (default `french`). The log format and the `replay` CLI output stay as the raw `"7C"` serialisation | Keeps the engine, log and protocol unchanged. Theme is a display-only concern; swapping it needs no engine, protocol or log changes. Single-cell glyphs keep the card-tile layout aligned in every terminal |
| D25 | 2026-11-18 | Meld builder uses a cycle model: pressing `m` enters a mode that iterates the already-legal `LayMeld` actions with `←/→`, `Enter` commits, `Esc` cancels. Same model for `a` + `AddToMeld`. No multi-select + validate | Simpler: reuses `legal_actions` directly, no selection-to-meld reconciliation. Cheaper to test and implement. Loses nothing, since the meld solver already enumerates every legal meld the player could want to lay |
| D26 | 2026-11-18 | `Player::act` becomes synchronous: `fn act(&mut self, obs, legal) -> Action`. | D27 | 2026-11-18 | Greedy agent: draw whichever source reduces the solver's unmatched total more (tie: stock). Always lay a legal meld or add to a meld when available. Discard the highest-rank unmatched card (ties broken by card index). Close whenever `can_close`. Pass only when no other action is legal. Deterministic | Smallest heuristic that ought to beat Random cleanly. Deterministic means eval runs are reproducible from the match seed alone |
| D28 | 2026-11-18 | Rule-based agent = greedy + discard-safety v1. Scores each legal discard by whether it fits any meld the next seat is visibly building (their `melds_on_table`) or completes a run with a card they recently took from the discard. Among discards tied on greedy value, pick the safest; else fall back to greedy. Per-turn state only | Simplest signal strong enough to beat greedy. Opponent-hand modelling (belief tracker) is m4's business; keeping m3 state-free keeps the two layers independent |
| D29 | 2026-11-18 | The m3 eval harness is headless and calls `rules.legal_actions` → `agent.act` → `rules.apply` directly against the m1 engine, bypassing the m2 server/transport. Duplicate deals: each paired game runs the same `Chance` seed twice with A/B on swapped seats. Single-threaded in m3; rayon deferred | Faster and fewer moving parts. The server's async transport layer serves live play, not batch simulation |
| D30 | 2026-11-18 | The design-doc m3 exit test's "rollouts per second" metric is recorded as "decisions per second" for m3 because baseline agents do no rollouts. The rollouts figure returns in m4 with the search agent | Baseline agents choose deterministically from a legal set; there is no rollout to measure. Decisions/sec captures the same operational concern (how fast eval can run) |
| D31 | 2026-11-18 | Stalemate terminal: a `StandardConga` hand ends as a `Stalemate` when any of the following fires — the engine would do a 4th reshuffle in the same hand (reshuffle count capped at 3), or a `DrawStock` finds both the stock and the reshufflable discard portion empty. On stalemate every seat scores 0, no bonus, dealer rotates normally. `HandResult` gains a `terminal: HandTerminal { Closed, Stalemate }` field so replay and the match log preserve the distinction. Rule clarification C4 in `docs/design.md`. Logged in `docs/plans/m3.md` as new slice 6 ahead of the renumbered exit-test slice 7 | Found in m3 slice 5 playtesting: two deterministic greedy-style agents can cycle a hand forever because `Close` is never offered (no 8-card configuration ever splits into 7-melded + 1 close card). The m1 engine already deferred this terminal case (`standard.rs:436 unreachable!`). Fixing it in the engine (rather than in the harness or in the agent) gives termination for every entry point — eval, server play, TUI — for free. K=3 lets each hand have three full cycles of card mixing before giving up. "Draw" scoring (0 points) matches the "nobody won this hand" reading; residual-scoring was considered and rejected to keep the match outcome non-exploitative (an agent cannot deliberately stall to score opponent residuals) |
| D32 | 2026-11-19 | Belief tracker is a hybrid: a stateful `HashMap<Seat, HashSet<Card>>` of cards each opponent definitely holds (inferred from `Drew{source=TopDiscard}` + later `Discarded`/`LaidMeld`/`AddedToMeld` events), plus uniform sampling over the unconstrained unseen cards. Lives in `conga-ai::belief`. Rule-based v2 and the search agent both consume it; `RuleSet::sample_state` stays stateless and uniform | The design doc's intent (line 311) is one `conga-ai` crate holding both belief and search. The stateful constraints give the information gain for free from events we already broadcast; uniform fill for unknowns matches the design-doc's "Version 1 samples uniformly among deals that fit these facts" (line 375). Particle filters and explicit per-card distributions buy nothing while events give hard 0/1 evidence |
| D33 | 2026-11-19 | Search family is PIMC with shared determinization: one belief sample per iteration, all legal actions scored against the same determinized world, averaged over K samples (default 50). Rollout policy is `GreedyPlayer` for both seats. Full-hand rollouts (no depth cap). Deferred to m5-m6: IS-MCTS, depth-limited rollouts with a learned leaf | Matches design-doc choice 1 (line 348) and the sample-budget sketch (line 401-403). Shared determinization reduces per-sample variance; greedy rollouts converge faster than random and reuse m3 infrastructure. Simplest path to a search agent that beats rule-based |
| D34 | 2026-11-19 | `StandardConga::sample_state` is defined only for `Phase::Draw` / `Phase::Discard`; in `Phase::Showdown` or `Phase::Ended` it panics. The search agent falls back to greedy in showdown. State fields not surfaced by the observation (`must_not_discard`, `reshuffles_this_hand`, `dealer`, `first_turn_done`) are reconstructed on a best-approximation basis (`must_not_discard = None`, `reshuffles_this_hand = 0`, `dealer = (current_seat - 1) mod seats_count`, `first_turn_done = [true; seats_count]`) | Showdown is heavily constrained (close + lay melds are forced, `Pass` vs `AddToMeld` is near-forced per D11/D16), so search buys little there and showdown sample_state would need to fabricate `closer`, `closer_hand_at_close`, `face_down_close` from information that isn't in the observation. The approximations in play-phase affect only first-ply legality at worst (a bounded error PIMC absorbs); observe() ignores every approximated field so conformance test 5 is satisfied |
| D35 | 2026-11-19 | Rule-based v2 ships only if it beats greedy over 1000 paired deals with Wilson LB > 0.5 and clears ≥ 55% win rate on three seed smokes (same seeds as m3). If it fails the gate, the slice is reverted before milestone acceptance; the m4 exit test then uses the existing (m3) rule-based agent as the "rule-based" opponent | Avoids re-shipping another underperforming heuristic (the D28 outcome). Bounds the downside: one slice's work at risk. Keeps the design-doc exit test ("search beats rule-based") meaningful whether v2 ships or not |
| D36 | 2026-11-19 | Search agent reads `rules` by holding its own clone (`StandardConga: Clone`), not by widening the `Player` trait. The search's rollout RNG is a `ChaCha8Rng` seeded from the agent's own seed; it drives both opponent sampling and the `Chance` source during rollouts. The real-game `Chance` is untouched | `Player::act(&mut self, obs, legal)` is the clean interface; adding a `&R` parameter to every player would churn baselines and the eval runner for one agent's convenience. Owning a rule-set clone is cheap (StandardConga is Copy-like with no large state). Determinism: same agent seed + same obs/event sequence produces the same action sequence |
| D37 | 2026-11-20 | Milestone 4 defers the standalone search agent to m7. `SearchPlayer` ships as scaffolding (compiles, beats `RandomPlayer` 100-0 over 50 games, available as `BaselineAgent::Search`) but is not subject to an m4 exit regression. The m4 exit test becomes "rule-based v2 beats greedy over 1000 paired deals" (D35 gate). The design-doc m4 exit test ("search beats rule-based") is pushed to m7 when the learned value model lands | Measured PIMC-with-greedy-rollouts vs greedy over 50 games at K=50: 4% (2/50). Two knobs probed at K=20 over 40 games each: random rollouts 0/40 (strictly worse because variance drowns signal), opp_weight 0.3 shaping 5/40 (12.5%, better but not winning). Diagnosis is structural strategy fusion: the rollout policy (greedy) is stronger than the root policy (search), so rollout values are calibrated for a trajectory that isn't the one played. Not fixable by value-function tuning — needs a non-greedy rollout leaf, which is exactly m7's value-model deliverable. Belief tracker (D32) remains the primary m4 win: it enables rule-based v2 and will plug into the m7 search unchanged |
| D38 | 2026-11-20 | Rule-based v2 is kept as a refactor despite missing the D35 gate. Measured on three 200-game smokes vs greedy: 35.5% / 37.0% / 34.0% (seeds 1, 0xC0FFEE, 0xBEEF). Statistically indistinguishable from the original D28 at 36-38%. v2 keeps the same scoring shape (meld-extension + rank/run-partner risk) but reads from the belief tracker's `known_held` instead of the ad-hoc `opponent_pickups` field, so the whole belief-consuming agent lives on one source of truth. D35's revert clause was aimed at preventing a *worse* heuristic from shipping; v2 is neither worse nor better than D28, so keeping it preserves code quality without accumulating technical debt. m4 exit test becomes "rule-based beats random" (already green from m3) plus the belief-tracker integration regressions; a rule-based agent that actually beats greedy is deferred to m5+ where match-equity gives it a stronger signal than the reactive-safety heuristic can | Cheapest honest ship. The "discard safety" shape (reactive avoidance of visible/inferred opponent partners) cannot overcome the residual cost of holding heavier cards — same conclusion as D28, now re-confirmed with better information. Beating greedy needs a different shape (match-equity-aware close/hold, belief-weighted draw selection) that is outside m4's scope |
| D39 | 2026-11-25 | 2-player match equity table is a dense 2D grid indexed by `(own_score, opp_score)` at 1-point resolution over `[-50, 110]` inclusive (161 × 161 = 25 921 cells). Dealer-agnostic: dealer alternates every hand in 2-player play, so any per-hand dealer bias averages out over a match. Scores outside the stored range clamp to the nearest edge. Elimination short-circuits the lookup before clamping: `own > 100` returns 0.0, `opp > 100` (with `own` not itself eliminated) returns 1.0. A dealer axis can be added in a later milestone if invariant tests show more than ~2 pp dealer asymmetry | Design-doc Building Block 5 requires a negative range with a floor without prescribing one; -50 covers the minus-50 conga + go-out bonus floor with no observed real match reaching it. 1-point resolution is the engine's native unit and avoids the interpolation bugs a coarser grid would invite near Close decisions. The 161² footprint is ~400 KB as pretty JSON, small enough to version-control. Starting dealer-agnostic keeps slice-3 compute at half the cost; adding a dealer axis later is cheap because the stored layout is append-friendly |
| D40 | 2026-11-25 | The 2-player equity table is computed by greedy-vs-greedy Monte Carlo. Only cells with `own ≤ opp` are simulated; the opposite half is filled via the mirror `equity(a, b) = 1 - equity(b, a)`. `N` matches per cell is chosen after a 1000-match smoke in slice 2 measures matches/sec on this machine, with a soft target of ≤ 15 minutes total wall-clock serial. `rayon` is only added if the smoke shows the serial budget exceeds that target, and only after bringing the numbers | Greedy is deterministic, strong (D28/D38 both miss it) and already available in `conga-ai`; using it as both agents keeps the table's semantics unambiguous. The mirror symmetry is exact for self-play and halves the sample budget for free. Deferring the rayon decision to post-smoke follows the CLAUDE.md rule "No `rayon` unless the sequential compute is actually too slow — bring numbers first" |
| D41 | 2026-11-25 | The score-aware agent is `RuleBasedPlayer` plus an equity-aware `Close` gate. On every legal `Close`, draw `K` samples (default `K = 20`) from `BeliefTracker::sample_state`, estimate the opponent's expected unmatched residual from each sample, compute the post-close scores (applying conga / go-out bonuses from the current situation), look up equity for the post-close `(own', opp')` and average across samples. Compare to a `continue_equity` approximated by the status-quo lookup `equity(own_current, opp_current)`. Close iff `post_close_equity > continue_equity`. On non-Close decisions the agent returns the base's choice unchanged | Close is the highest-leverage score-sensitive decision — it locks in a score delta that other actions can only predict. Keeping Draw/Discard on the base preserves a clean paired comparison against the score-blind rule-based (same code path everywhere except the one equity gate). Belief sampling tightens the opponent-residual estimate against a uniform prior and reuses the m4 primitive without introducing a new one. The status-quo approximation for `continue_equity` is a first pass; slice-4 pivot room is tracked in the plan |
| D42 | 2026-11-25 | m5 exit test: the score-aware agent beats rule-based v2 over 1000 paired deals (2000 matches total, seats swapped per seed) with Wilson lower bound > 0.5 at 95%. Secondary reporting in the slice-5 regression: mean score, hands/match, and equity-table invariants (origin ≈ 0.5, elimination boundaries 0.0 / 1.0, mirror symmetry, monotonicity in own) that are already unit-tested on the real table in slice 3 | Mirrors the D35 gate so successive milestones can be compared on the same precedent. 1000 paired deals at ~35% baseline variance (m4 smokes) is enough precision to catch a 5 pp edge cleanly without the test becoming slow (<~60 s at release optimisation) |
