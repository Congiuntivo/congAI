# Milestone 5 plan — match equity and score-aware play

## Context

Design-doc goal (Building block 5 "Match value" and the Objective row of the design-matters table): the project reward is match win probability through an equity table. Milestone 5 realises that for the 2-player case: a match-equity table, plus a score-aware agent that beats its score-blind version over full matches.

Why now:
- m4 landed `BeliefTracker` (D32) and a scaffolding `SearchPlayer` (D33, D37). Rule-based v2 is statistically identical to v1 against greedy (D38). The m4 writeup argues a rule-based that actually beats greedy needs a different shape — match-equity-aware rather than reactive-safety-only — which is this milestone.
- Builds on the belief tracker without changing `RuleSet` or `Player::act`.

What this plan does not touch (per the kickoff prompt):
- No change to `Player::act` or the `RuleSet` trait.
- No search changes.
- No `rayon` unless the serial compute is actually too slow, and only after bringing measured numbers.

## Decisions settled with Simone (to be logged as D39–D42 in `docs/decisions.md` at slice 1)

- **D39 — equity table shape.** 2D table indexed by (own_score, opp_score), 1-point resolution, score range [-50, 110] inclusive (161 × 161 = 25,921 cells). Dealer-agnostic (dealer alternates each hand; bias averages). Out-of-range scores clamp to the nearest edge. If either score > 100 the lookup short-circuits (0.0 if own > 100, 1.0 if opp > 100 and own ≤ 100). Can add a dealer axis in a later milestone if invariant tests show >~2pp dealer asymmetry.
- **D40 — equity table compute.** Greedy vs greedy self-play (deterministic, strongest simple baseline). Use the symmetry `equity(a, b) = 1 - equity(b, a)` to halve work: compute only own ≤ opp. N per cell is chosen after a 1000-match smoke measures matches/sec on this machine; target total compute ≤ 15 min serial. `rayon` only if smoke numbers show serial > 15 min, with numbers in the slice stop report.
- **D41 — score-aware agent.** Base = `RuleBasedPlayer`. Only the `Close` decision consults the equity table: at a legal `Close`, sample K opponent hands via `BeliefTracker::sample_state`, estimate expected opponent unmatched residual, compute post-close vs continue-playing scores and look up equity. Close iff post-close equity > continue equity. Belief sampling (default K=20) tightens the opp-residual estimate versus a uniform prior and is the agent's one scoring-time use of the m4 belief work.
- **D42 — m5 exit test.** 1000 paired deals (2000 matches). Wilson LB on the score-aware agent's win rate against its score-blind base (rule-based v2) must exceed 0.5 at 95%. Mirrors the D35 gate. Secondary reporting: mean score, hands/match, invariant tests on the equity table itself.

### Slice 4 — ScoreAwarePlayer + wiring

- **Goal.** Implement the score-aware agent per D41 and wire it as `BaselineAgent::ScoreAware`, available as `--ai score-aware` in both `eval` and `play`.
- **Files.**
  - `crates/conga-ai/src/score_aware.rs` (new) — `ScoreAwarePlayer { base: RuleBasedPlayer, belief: BeliefTracker, rng: ChaCha8Rng, samples: u32, table: &'static EquityTable }`. Implements `Player`:
    - `notify` forwards to `base` and `belief`.
    - `act`: ask `base` what it would do. If the base's choice is a `Close`, run the equity gate: sample K belief states, in each estimate opp expected unmatched residual (sum of ranks after `conga-core::meld` solve on the sampled opponent hand, minus whatever meld points they've laid down — reuse existing scoring from `conga-rules`). Compute own and opp post-hand scores (conga/go-out bonuses from the current situation), look up `equity(own', opp')`. Average over K samples. Compare to the "don't close now" expected equity (approximated as the current scores' equity — see implementation note below). Close iff `post_close_equity > continue_equity + epsilon` (epsilon = 0.0 initially; tunable).
    - If the base's choice is not a `Close`, return it unchanged.
    - Open design question for the implementation PR: how to compute `continue_equity` without a full rollout. Starting proposal: use `table.lookup(own_current_scores, opp_current_scores)` as "if the hand just ended with status quo". If this proves too crude, swap to a one-step lookahead.
  - `crates/conga-ai/src/lib.rs` — `pub mod score_aware;` and re-export `ScoreAwarePlayer`.
  - `crates/conga-ai/src/eval.rs` — add `BaselineAgent::ScoreAware(Box<ScoreAwarePlayer>)`, update `from_name`, `from_name_with_samples`, `names`, `impl Player for BaselineAgent`.
  - `crates/conga-cli/src/main.rs` — add `"score-aware"` to the `--ai` value_parser lists in `Play` and `Eval`.
  - `crates/conga-cli/src/{play.rs,eval.rs}` — wire the new name (changes look purely mechanical).
- **Tests.**
  - `score_aware_closes_when_equity_wins` — craft a state where own scores jump from 60 → 50 (good) if closing now and opp jumps from 50 → 90 (bad for opp); assert agent closes.
  - `score_aware_declines_close_when_equity_warns` — craft a state where closing now would cross own into elimination (e.g., own 95 and post-close delta pushes to 101) and continue-equity is still positive; assert agent does NOT close.
  - `score_aware_matches_base_on_non_close` — on a draw/discard decision, assert the agent returns the same action as `RuleBasedPlayer` on the same state.
  - `score_aware_legal_over_random_states` — property-ish: 200 random reachable states, assert agent returns a legal action every time.
  - A short smoke eval (not a regression yet): `score_aware` vs `rule-based` at 100 games. Not `#[ignore]`d; checks the agent doesn't panic or hang.
- **Check.** Full workspace `cargo test`.
- **Try it.** `cargo run -p conga-cli --release -- eval --a score-aware --b rule-based --games 100 --seed 1`. Then `cargo run -p conga-cli --release -- play --seed 1 --ai score-aware --log /tmp/sa.jsonl`.

## Risks and fallbacks

- **The real equity table might make slice 4 fail the exit test.** Possible causes: Close is not the high-leverage decision we think it is; the belief-based opp-residual estimate is too noisy; the "continue_equity = status-quo lookup" approximation is too crude. In that order, mitigations: (1) extend equity consult to Discard high-vs-low choices, (2) raise K from 20 to 50, (3) add a one-step lookahead for `continue_equity`. Any of these would come as a slice-4-pivot commit with a diagnostic eval, same shape as m4's D37 diagnostic knobs.
- **The real equity-table compute might be too slow serial.** Smoke numbers in slice 2 decide this. If > 15 min, bring numbers and either reduce N, drop to a 5-pt grid with interpolation, or add `rayon`.
- **`run_match` may not accept starting scores.** If so, extend its signature in slice 2 with a `starting_scores: Option<[i32; N]>` parameter, default None = 0-0. Not a public breakage: all current callers pass None.
