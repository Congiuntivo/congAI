# Milestone 2: game server, protocol, in-memory transport, TUI

## Context

Milestone 1 is accepted (`m1-accepted` on `main`). The engine, the `RuleSet` trait, the meld solver and `StandardConga` all exist with 84 tests green; `GameLog` + `replay` already reproduce a single hand exactly (slice 8). Rule clarifications C1, C2, C3 are encoded.

Milestone 2 adds the layers above the engine: a serializable protocol, an authoritative server with a match-level loop, an in-memory transport, a terminal client and a minimal random AI. The exit test is one full 2-player match in the TUI vs the random agent, with the saved log replayable via the CLI and producing identical states.

Nothing in m2 needs `axum`, WebSocket, Python or the full baseline suite; each is deferred to the milestone that first needs it.

## Known facts I rely on

From `docs/design.md`:
- Design rule 1: server authoritative from day one; a local game runs the same server over an in-memory transport.
- Design rule 2: one `observe(state, seat)` function is the only point hidden information is filtered.
- Design rule 3: a game is stored as ruleset id, every shuffle result and the action list.
- Design rule 7: every message, log and trained model is stamped with protocol version and ruleset hash.
- The six protocol details in Play modes: per-seat event sequence numbers, turn number on actions, reserved fields for a turn timer / timeout, AI take-over, seed stays server-side, hints are a server permission.
- Choice 3 is JSON (confirmed as D18).
- The Software components table pins `conga-protocol` to `serde` + `serde_json`, `conga-server` to `tokio` (and `axum` later), `conga-tui` to `ratatui` + `crossterm`.

From `docs/decisions.md`:
- D2 Rust for engine/server/TUI/search. D4 rules pluggable via `RuleSet`. D5/D6 slice workflow + branch per milestone.

From `m1` source code (verified by reading):
- `conga-core` exports `Action`, `Event`, `Observation`, `HandResult`, `Phase`, `MatchStatus`, `RuleSetId`, `GameLog`, `ReplayedHand`, `Card`, `Hand`, `Meld`, `Seat`. No serde derives yet.
- `GameLog` is a per-hand record (`starting_scores`, `dealer`, `shuffles`, `actions`). A match log is a sequence of such records plus headers and a terminal status line.
- `replay::replay` already reconstructs a hand's state sequence; the match replay layers hand loops on top of it.
- `StandardConga::State::face_down_close` is hidden; `observe` already respects it. The protocol needs no new filtering.

### Slice 2 — `conga-protocol` crate: versioned envelope + Message enums

**Files**: new `crates/conga-protocol/{Cargo.toml, src/lib.rs, src/message.rs, src/envelope.rs, src/io.rs}`.

**Content**:
- `PROTOCOL_VERSION: u32 = 1`.
- `Envelope<B> { protocol_version: u32, ruleset_hash: u64, body: B }` on every message.
- `ClientToServer`:
  - `Act { turn: u32, action: Action }` (protocol detail 2).
  - `Resume { since_event_seq: u32 }` — reserved, unused in m2 (protocol detail 1, reconnect in m9).
- `ServerToClient`:
  - `Observe { turn: u32, observation: Observation }`.
  - `AwaitAction { legal: Vec<Action>, turn_timer_ms: Option<u32>, timeout_policy: Option<TimeoutPolicy> }` — timer / timeout fields reserved and `None` in m2 (protocol detail 3).
  - `Event { seq: u32, event: Event }` — per-seat sequence numbers (protocol detail 1). Server stamps `seq` per recipient seat.
  - `HandEnded { result: HandResult }`.
  - `MatchEnded { status: MatchStatus, final_scores: Vec<i32> }`.
  - `Error { code: ErrorCode, message: String }` — e.g. `IllegalAction`, `WrongTurn`, `ProtocolMismatch`.
- `TimeoutPolicy` is a two-variant stub (`DisconnectOnTimeout`, `TakeOverByAi`) — enum only, no behaviour in m2 (protocol detail 4 preparation).
- `io.rs`: `read_message<R: BufRead, M: DeserializeOwned>(r: &mut R) -> Result<M, ProtocolError>` and `write_message<W: Write, M: Serialize>(w: &mut W, m: &M) -> Result<(), ProtocolError>`. One JSON object per line, terminated with `\n`.

**Tests**:
- Round-trip every message variant through an in-memory reader/writer.
- `read_message` detects protocol-version mismatch and returns `ProtocolMismatch`.
- A line that is not valid JSON produces a `ParseError`, not a panic.

**Dependencies added**: `serde`, `serde_json`, path-dep on `conga-core` with `features = ["serde"]`. No tokio in this crate — it is sync JSON IO, usable from blocking or async contexts.

### Slice 3 — `conga-server` crate: `Transport` trait + in-memory impl

**Files**: new `crates/conga-server/{Cargo.toml, src/lib.rs, src/transport.rs, src/transport/in_memory.rs}`.

**Content**:
- `trait Transport: Send` with native async methods:
  ```rust
  async fn send(&mut self, msg: ServerToClient) -> Result<(), TransportError>;
  async fn recv(&mut self) -> Result<ClientToServer, TransportError>;
  ```
  `send` and `recv` take `&mut self` so a single seat's transport is owned by the server loop. A separate client-side half (`ClientEnd`) exposes the mirror pair.
- `InMemoryTransport` built on `tokio::sync::mpsc`: a pair `(ServerEnd, ClientEnd)` where messages are sent through unbounded channels. One pair per seat.
- `TransportError` covers `ChannelClosed` and `Protocol(ProtocolError)` from slice 2. No time outs yet; that is a later milestone.
- No `MatchState`, no hand loop here. This slice is just the transport primitive and its channel plumbing.

**Verification that this does not block m9 WebSocket**: the trait takes `&mut self` and returns owned messages. An `axum::ws::WebSocket` wrapper implements the same two methods by reading/writing JSON frames. No design change needed when WS lands.

**Tests**:
- `InMemoryTransport::pair()` round-trips one message in each direction via `#[tokio::test]`.
- Dropping the client half makes the server's `recv` return `ChannelClosed`.

**Dependencies added**: `tokio` with features `rt-multi-thread`, `macros`, `sync`; path-deps on `conga-core`, `conga-protocol`.

### Slice 4 — `MatchState` + hand orchestrator + JSON-line match log

**Files**: `crates/conga-server/src/{match_state.rs, server.rs, log.rs}`.

**Content**:
- `MatchState { seats_count: u8, scores: Vec<i32>, dealer: Seat, hands_played: u32, status: MatchStatus }`.
  - `fn new(seats: u8, starting_dealer: Seat)` initialises zero scores.
  - `fn start_hand(&self) -> HandPrep` returns `{ scores, dealer }` for the engine's `new_hand`.
  - `fn finish_hand(&mut self, rules: &R, result: &HandResult)` updates scores, rotates dealer by `+1 mod seats` (rule 16), consults `rules.match_status(&self.scores)` and sets `self.status`.
- `GameServer<R: RuleSet, L: MatchLogWriter>`:
  - Holds `rules`, `MatchState`, one `Transport` per seat, a `RandomChance` driven by the match seed, and a log writer.
  - `async fn run(&mut self)` loops: for each hand, prepare → `new_hand` → turn loop → `hand_result` → log → finish → check `match_status`. Stops when `status != InProgress`.
  - Turn loop per hand: `observe` for current seat → `send AwaitAction + Observe` → `recv Act` → validate `action ∈ legal_actions(state)` (reject with `Error { IllegalAction }` and re-prompt) → `apply` → broadcast each produced event to every seat as `ServerToClient::Event { seq, event }` with a per-seat monotonically-increasing sequence counter (protocol detail 1).
  - The server **never** trusts a client: every action is checked against `legal_actions` before `apply`. There is no engine call that bypasses this.
- Match log format (JSON-lines, one object per line):
  - `{"type":"match_header","protocol_version":1,"ruleset_id":{...},"seats":2,"starting_dealer":1,"seed":...}`
  - Per hand:
    - `{"type":"hand_header","index":0,"dealer":1,"starting_scores":[0,0]}`
    - `{"type":"shuffle","cards":[...]}` (possibly multiple per hand due to the rule-14 reshuffle)
    - `{"type":"action","seat":0,"turn":5,"action":{...}}` for every applied action
    - `{"type":"hand_result","result":{...}}` as a cross-check during replay
  - `{"type":"match_end","status":{...},"final_scores":[...]}`
  - The log contains only facts the server generated; it never echoes client-sent messages verbatim.
  - Events are not logged — they are a function of (state, action) and the replay path recomputes them.
- `MatchLogWriter` trait: `write_record(&mut self, rec: &MatchLogRecord)`. Impls: `JsonLinesWriter<W: Write>` and `NullWriter` (for tests that do not care).

**Tests**:
- A scripted 2-player match using two in-memory transports and hand-coded action sequences produces the expected scores and `MatchStatus`. Uses a seeded `ChaCha8Rng` for determinism.
- Sending an action that is not in `legal_actions` yields a `ServerToClient::Error { IllegalAction }` and the server re-prompts the same seat.
- Rule-16 tie-break: forge scores so all remaining players go out together on the same hand; the winner is the lowest-scoring seat.
- Dealer rotates by `+1 mod seats_count` between hands.

**Dependencies added**: none beyond slice 3.

### Slice 5 — `conga-ai` crate: `Player` trait + `RandomPlayer`

**Files**: new `crates/conga-ai/{Cargo.toml, src/lib.rs, src/player.rs, src/random.rs, src/driver.rs}`.

**Content**:
- `trait Player: Send { async fn act(&mut self, obs: &Observation, legal: &[Action]) -> Action; fn notify(&mut self, event: &Event) {} }`. The `notify` default is a no-op; `RandomPlayer` does not need it.
- `RandomPlayer<R: Rng>` samples uniformly over `legal`. Exposed as `RandomPlayer::from_seed(u64) -> Self` (ChaCha8) and `RandomPlayer::new(rng)`.
- `driver::run_player<P: Player, T: Transport>(player: P, transport: T) -> Result<(), DriverError>`: the client-side loop. Reads `ServerToClient` messages, keeps the last observation, when `AwaitAction` arrives calls `player.act` and sends back `Act`. Exits on `MatchEnded`.
- `conga-ai` depends only on `conga-core`, `conga-protocol`, `conga-server` (for `Transport`), `rand_core` (already in workspace), `rand_chacha` (already in workspace). No `tokio` feature beyond `sync` — the driver's async comes from the transport.

**Tests**:
- `RandomPlayer::act` on a hand-built list of legal actions returns one of them, repeatedly.
- Distribution check: 10,000 calls on a 4-action list keep each count within 3σ of uniform.
- `driver::run_player` paired with a mock `Transport` that sends one `AwaitAction` and then `MatchEnded` exits cleanly after emitting one `Act`.

**Dependencies added**: `conga-ai` crate itself. No new workspace deps beyond what slices 1–3 added.

### Slice 6 — `conga-tui` crate: terminal client

**Files**: new `crates/conga-tui/{Cargo.toml, src/lib.rs, src/app.rs, src/render.rs, src/input.rs, src/driver.rs}`.

**Content**:
- `ratatui` 0.30 with the `crossterm` backend. Terminal setup (enter / leave raw mode, mouse off, alternate screen on) wrapped in a guard type that restores the terminal on drop even on panic.
- One screen for now: own-seat view. Layout:
  - Top: scores, dealer, hand index, current seat, phase.
  - Middle: own hand grouped by the meld solver's best split, same format the m1 debug CLI uses. Red for hearts / diamonds, default for clubs / spades.
  - Below hand: top discard, stock size, melds on table.
  - Bottom: numbered list of legal actions and a one-line status (last event, errors from the server).
- Input: `crossterm::event::Event::Key` digits select an action, `l` dumps the recent events, `q` quits. No hints, no AI output. Mouse ignored.
- `driver::run_tui<T: Transport>(transport: T) -> Result<(), DriverError>`: the TUI's equivalent of `run_player`. Reads messages from the transport, repaints on each `Observe`, blocks on key input only when an `AwaitAction` is live, sends `Act` on selection. Exits on `MatchEnded`.
- Rendering code is split from driver code so the renderer can be unit-tested against a fixed observation without a live terminal.

**Tests**:
- Unit test: `render_hand(obs, hand_eval) -> Vec<Spans>` on a hand-built observation produces the expected ordering (meld cards first, then `|`, then unmatched cards with values in parens).
- Unit test: the key-to-action resolver maps `'1'..'9', '0'` to the right index and rejects numbers past `legal.len()`.
- No end-to-end TUI integration test. The exit test is manual play (see Verification).

**Dependencies added**: `ratatui = "0.30"`, `crossterm` at the version ratatui 0.30 re-exports. Both workspace deps.

### Slice 7 — `conga-cli`: `play` and `replay` subcommands

**Files**: `crates/conga-cli/src/{main.rs (updated), play.rs (new), replay.rs (new)}`.

**Content**:
- `conga-cli play --seed <u64> --players 2 --log <path>`:
  - Builds `StandardConga`, a `MatchState` (starting dealer = seat 1 so seat 0 plays first — matching the m1 debug CLI convention), a JSON-lines `MatchLogWriter` writing to `<path>`, two in-memory transport pairs.
  - Spawns one `tokio::task` for the server loop, one for `run_tui` (seat 0), one for `run_player(RandomPlayer::from_seed(seed ^ 0xA1), ...)` (seat 1). Awaits all three. `--players 2` is the only supported value in m2 (clap enforces); the `--players` flag is kept for future expansion rather than removed.
  - On exit the terminal is restored (slice-6 guard) and the final `MatchStatus` is printed on stdout after the raw-mode teardown.
- `conga-cli replay <log-file>`:
  - Reads the JSON-lines file line by line.
  - Reconstructs the trajectory: for each hand record, builds a `GameLog` (ruleset id + starting scores + dealer + shuffles + actions) and calls `conga_core::log::replay`. Prints a textual rendering of each state in sequence, then the `HandResult`, then (at end) the `MatchStatus`.
  - If the replayed `HandResult` disagrees with the one in the log (cross-check), fails loudly with a diff — this is the exit-test guarantee that replay is faithful.

**Tests**:
- End-to-end: scripted stdin-free match with two `RandomPlayer`s (no TUI), writes a log, feeds the log back through `replay`, asserts that every `HandResult` in the log matches the replayed one and that the final `MatchStatus` matches.
- Golden string for one short hand rendered by `replay`. Hand-written expected string in the test file; no `insta` crate.
- CLI arg parsing: `clap` rejects `--players 3` in m2 with a clear error (m3 relaxes this).

**Dependencies added**: none beyond slices 1–6.

**Files**: `crates/conga-tui/src/{app,input,driver,render}.rs`; `crates/conga-tui/tests/input.rs`.

**Content**: `AppState::hand_order: Vec<Card>` is the TUI's display order of the own hand. Rebuilt on each `Observe`: keep prior order for cards still in `obs.own_hand`, append new cards after the cursor, drop missing ones. `Shift+←` / `Shift+→` swap the selected card with its neighbor in `hand_order`. Everything downstream (`render_hand_strip`, cursor math) reads `hand_order` instead of `obs.own_hand.iter()`.

**Tests**:
- `rebuild_hand_order([A,B,C], &obs{A,C,D}) == [A,C,D]` (B dropped, D appended).
- `rebuild_hand_order([A,B,C], &obs{A,B,C})` stable.
- `swap_right(hand_order, 2) == new vec with [2] and [3] swapped`.
- Swap at the right edge is a no-op.

**Dependencies added**: none.
