# Milestone 6 plan: explanation tools and the validation loop

Branch: `m6-explanations` (from `main` at `m5-accepted`).

## Context

Milestone 5 shipped the first non-scaffolding ladder-climber: `ScoreAwarePlayer` beats rule-based by ~7pp, almost all of it from *picking the close-card that leaves a clean split* (D45). The equity-gated "decline to close" path was a no-op under N=50 table noise; the real signal lives in close-card selection against a shared belief sample.

Milestone 6 turns that observation into a tactic a human can state, and proves the validation loop that future tactics will pass through. The design-doc exit test is *the first tactic passes the loop on fresh seeds*.

## Decisions settled (logged as D46-D49 in `docs/decisions.md`)

- **D46** — Explanation methods for m6: **disagreement mining** and **counterfactual probes**. Per-action values, value decomposition, distillation, feature attribution, targeted experiments deferred. Both chosen methods operate on score-aware + belief + equity (no SearchPlayer dependency, no value model).
- **D47** — First candidate tactic: **"when closing, pick the close-card that leaves the cleanest split against a shared belief sample"**. Known-good from D45; wraps rule-based so we can measure the tactic in isolation. Doubles as a smoke test that the loop works on a known-good candidate.
- **D48** — Code structure: new `conga-ai::features` module computing feature vocabulary on-demand from `Observation` + `BeliefTracker`, bounded to m6's needs. Candidate tactics each live as their own `Player` wrapper under `conga-ai::candidates::`, composing any inner player. No touch to `RuleBasedPlayer`. No new `BaselineAgent::from_name` entry unless the candidate passes the loop.
- **D49** — Validation harness: 500 paired deals = 1000 matches per gate. Pass rule: Wilson LB > 0.5 vs unchanged baseline. Gain-vs-strong (score-aware) reported with Wilson CI but informational, not a pass/fail.

Also:
- Committed diagnostic artefacts live under `crates/conga-ai/diagnostics/` (sibling to `assets/`). Kept small (CSV / short JSON). `assets/` stays the home of runtime-loaded data.

### Slice 1 — `conga-ai::features` module

Goal: a single surface for "feature vocabulary from Observation + BeliefTracker" that disagreement mining, counterfactual probes and tactic candidates can share.

Files:
- `crates/conga-ai/src/features.rs` (new). Public `Features` struct with named fields, serde derivations. One public function `extract(obs: &Observation, belief: &BeliefTracker, rules: &StandardConga) -> Features`.
- `crates/conga-ai/src/lib.rs` — add `pub mod features;`.

Scope (minimum needed for the first candidate + disagreement mining; add more later only when a slice needs them):
- `unmatched_total: i32` (from `rules.evaluate_hand(own_hand).unmatched_total`)
- `unmatched_count: u8`
- `meld_count: u8`
- `one_away_count: u8` (cards one draw away from a meld — enumerate missing cards against the stock+hidden pool)
- `own_distance_to_elim: i32` (100 − own_score, floored at 0)
- `opp_distance_to_elim: i32` (closest opponent)
- `top_discard: Option<Card>`
- `turn_number: u32` (derived from discard_history length)
- `known_opp_cards_count: u8` (sum of `belief.known_held(seat).len()` over opponents)

Tests (new file `crates/conga-ai/src/features.rs` inline `#[cfg(test)]`):
- Each feature extracted from a hand-built `Observation` + `BeliefTracker` on 3-4 fixtures (empty hand, full meld, mixed). Check every field.
- Snapshot-style: a single known fixture with all fields pinned.

Check: three CLAUDE.md commands.

Try it by hand: no CLI yet; verified via tests.

Commit: `m6: slice 1 — features module (D48)`.

### Slice 2 — Disagreement mining, with committed diagnostic

Goal: find positions where score-aware and rule-based pick different actions, group by `Features`, commit the table as a diagnostic artefact.

Files:
- `crates/conga-ai/src/disagreement.rs` (new). Public `mine_disagreements(seeds: &[u64], max_per_seed: usize) -> Vec<DisagreementRow>`. `DisagreementRow { seed, turn, features, score_aware_action, rule_based_action, equity_at_score_aware_action: f32, equity_at_rule_based_action: f32 }`.
- `crates/conga-cli/src/main.rs` — new subcommand `mine-disagreements --seeds N --out <path>` that writes CSV.
- `crates/conga-ai/diagnostics/m6_disagreements.csv` (new, committed). Produced by running `conga-cli mine-disagreements --seeds 50 --out crates/conga-ai/diagnostics/m6_disagreements.csv`. Keep it small (<200 rows).
- `crates/conga-ai/src/lib.rs` — add `pub mod disagreement;`.

Mechanics: play score-aware vs score-aware with seeded ChaCha8 for N seeds. At each `Phase::Draw` or `Phase::Discard` decision (current_seat == own_seat), compute both agents' chosen actions against the same observation + belief. If they differ, record a row with features, actions and equity-at-each-action (for Close actions, use the post-close equity lookup; for others, use the status-quo equity lookup — the equity-after-action for non-Close actions is an approximation we note in a doc comment).

Tests:
- Unit test: mine on one seed, assert at least one disagreement surfaces at a Close position (we know D45 gives a signal there).
- Unit test: `DisagreementRow` serde round-trip via CSV writer.
- Smoke test (`#[ignore]`d): mine on 50 seeds, assert >=10 rows total.

Check: three CLAUDE.md commands.

Try it by hand: `cargo run -p conga-cli -- mine-disagreements --seeds 10 --out /tmp/dis.csv`, open in a spreadsheet.

Commit: `m6: slice 2 — disagreement mining + diagnostic (D46)`.

### Slice 3 — Counterfactual probes

Goal: given a position, systematically perturb one input and record which perturbations flip score-aware's chosen action. Commit a sweep over a handful of positions drawn from slice-2's disagreement table.

Files:
- `crates/conga-ai/src/counterfactual.rs` (new). Public `probe(position: &CounterfactualPosition, agent: &dyn Player) -> Vec<CounterfactualRow>`. `CounterfactualPosition { obs, belief_state, legal_actions }`. `CounterfactualRow { perturbation, original_action, new_action, equity_delta }`.
- Perturbations (bounded, deterministic set):
  - Own score ±5, ±10 (clamped to valid range).
  - Opp score ±5, ±10.
  - For each belief-known opponent card: remove it (treat as unknown).
  - For Close positions: swap the close-card.
- `crates/conga-cli/src/main.rs` — new subcommand `counterfactual-sweep --from <disagreement-csv> --n 10 --out <path>`. Reads the top-N disagreement rows, reconstructs each position (seed + turn), runs `probe`, writes JSON.
- `crates/conga-ai/diagnostics/m6_counterfactuals.json` (new, committed).
- `crates/conga-ai/src/lib.rs` — add `pub mod counterfactual;`.

Open question flagged for slice 3 (address during build, no stop needed): reconstructing a position from seed+turn needs a deterministic replay. We already have event-log replay; wire it to the probe.

Tests:
- Unit test: build a Close position by hand, probe close-card perturbations, assert at least one perturbation changes the chosen action (D45's premise).
- Unit test: score perturbation at a position deep in the game flips to an elimination-aware action.
- Smoke test (`#[ignore]`d): sweep 10 positions from the committed disagreement CSV, assert output is well-formed.

Check: three CLAUDE.md commands.

Try it by hand: `cargo run -p conga-cli -- counterfactual-sweep --from crates/conga-ai/diagnostics/m6_disagreements.csv --n 5 --out /tmp/cf.json`.

Commit: `m6: slice 3 — counterfactual probes + diagnostic (D46)`.

### Slice 4 — Validation harness + candidate tactic wrapper

Goal: a reusable `validate_tactic` function and the first candidate as a `Player` wrapper on rule-based.

Files:
- `crates/conga-ai/src/validation.rs` (new). Public `validate_tactic<FT, FU, FS>(tactic: FT, unchanged: FU, strong: FS, pairs: u32, seed: u64) -> ValidationReport` where each builder is `impl Fn() -> Box<dyn Player>`. `ValidationReport { vs_unchanged: EvalReport, vs_strong: EvalReport, passed: bool }`. `passed = vs_unchanged.wilson_lb > 0.5`.
- `crates/conga-ai/src/candidates/mod.rs` and `crates/conga-ai/src/candidates/clean_split_close.rs` (new). `CleanSplitCloseWrapper<P: Player> { inner: P, belief: Option<BeliefTracker>, rng: ChaCha8Rng, samples: u8 }`. `Player::act` delegates to `inner`; if result is `Close(_)`, enumerate legal Close actions, sample K belief states, average equity lookups, pick the best. `notify` forwards to both inner and belief.
- `crates/conga-ai/src/lib.rs` — add `pub mod validation;` and `pub mod candidates;`.

Tests:
- Unit test (dummy good tactic): `validate_tactic(|| GreedyPlayer, || RandomPlayer, || RandomPlayer, 50, 0)` — asserts `passed == true`, Wilson LB > 0.5.
- Unit test (dummy bad tactic): `validate_tactic(|| RandomPlayer, || GreedyPlayer, || GreedyPlayer, 50, 0)` — asserts `passed == false`.
- Unit test (wrapper semantics): `CleanSplitCloseWrapper` on a hand-built Close position returns the clean-split option when available; forwards non-Close actions unchanged.

Check: three CLAUDE.md commands.

Try it by hand: no CLI flag yet (wrapper not in `BaselineAgent::from_name` until it passes).

Commit: `m6: slice 4 — validation harness + clean-split candidate (D47, D49)`.

## Exit test tracking

Primary: clean-split close-card tactic passes the loop on fresh seeds (Wilson LB > 0.5 vs unchanged rule-based, outside the CI).

Fallback: if the tactic fails, the loop still demonstrates correctness via the slice-4 unit tests on dummy good / bad tactics. The result file documents the negative outcome with a hypothesis.

## What I don't know yet

- Whether reconstructing a position from `(seed, turn)` in slice 3 requires exporting a new helper from `conga-server` or can go through the existing replay path in `conga-core`. Will investigate at slice-3 start; may need to stop and ask.
- Whether `one_away_count` should count cards one draw away from a *new* meld or from *extending* an existing meld. Will ask at slice 1 if the implementation is ambiguous; default to "new meld" since that's what the design-doc feature vocabulary implies.
- Whether `validation` should pass the same `PairedResult` seeds to both gates (so the same positions test both comparisons) or fresh seeds for each gate (independent evidence). Default: same seeds across gates for apples-to-apples; ask at slice 4.
